# 1 Le protocole HTTP

## 1.1. Un échange HTTP

```bash
curl --http1.1 -i https://example.com
```
> -i tells curl to print the response headers in addition to the body. Without it, you only see the HTML.

**Questions :**

1. Quelle est la première ligne affichée ? Que représente-t-elle ?
> **Le corrigé:** Première ligne : HTTP/1.1 200 OK. C’est la ligne de statut de la réponse : version du protocole, code de statut, message associé.

2. Que signifie le nombre `200` ?
> **Le corrigé:** Le nombre 200 : code de succès, la requête a été traitée correctement et la ressource est renvoyée.
3. À quoi correspondent les lignes qui suivent ?
> **Le corrigé:** Les lignes suivantes : les en-têtes de la réponse (Content-Type, Content-Length, Date, Server, Cache-Control...), au format Nom: valeur.
4. À partir de quelle ligne commence le contenu de la page ?
> **Le corrigé:** Début du contenu : après la première ligne vide, qui sépare les en-têtes du corps.
5. Dans quel langage ce contenu est-il écrit ?
> **Le corrigé:** Langage : HTML (le contenu commence par <!doctype html>).

## 1.2. Requête HTTP

```bash
curl --http1.1 -v https://example.com
```
**Questions :**

1. Quelle est la méthode HTTP utilisée ?
> GET.

2. Quelle est la ressource demandée ?
> / (la racine du site).

3. Quelle est la version du protocole HTTP ?
> HTTP/1.1.

4. À quoi correspond l'en-tête `Host` ?
> Le nom de domaine du site visé (example.com).

5. Pourquoi le navigateur doit-il envoyer une requête au serveur ?
> HTTP est un protocole client/serveur. Le serveur est passif et ne répond que lorsqu’on lui demande une ressource.

## 1.3. Codes de réponse
```bash
curl --http1.1 -i https://httpbin.org/status/200
curl --http1.1 -i https://httpbin.org/status/301
curl --http1.1 -i https://httpbin.org/status/404
curl --http1.1 -i https://httpbin.org/status/500
```

Complétez le tableau :

>| Code | Signification générale |
>|---|---| 
>| 200 | OK : succès, la ressource est renvoyée |
>| 301 | Moved Permanently : redirection permanente, la nouvelle adresse >est dans l’en-tête Location|
>| 404 | Not Found : ressource introuvable sur le serveur |
>| 500 | Internal Server Error : erreur interne du serveur |

**Question :** Expliquez la différence de résultat entre
```bash
curl -i http://google.fr
et 
curl -iL http://google.fr
```

> Sans -L, curl affiche la réponse de redirection (301 Moved Permanently avec Location: http://www.google.fr/) et s’arrête là.
> Avec -L, curl suit la redirection : il envoie une seconde requête vers l’adresse indiquée et affiche aussi la réponse finale (typiquement 200 OK avec la page HTML).

## 1.4. Dans le navigateur

Ouvrez Firefox ou Chromium et rendez-vous sur https://example.com.

1. Ouvrez les outils de développement (touche F12).
2. Sélectionnez l'onglet **Réseau** (*Network*).
3. Rechargez la page.
4. Sélectionnez la première requête correspondant au document HTML.

Repérez les informations suivantes :

- La méthode HTTP.
> GET
- L'URL demandée.
> https://example.com/
- Le code de réponse.
> code 200
- Les en-têtes de la requête.
- Les en-têtes de la réponse.
- Le contenu de la réponse.

**Question :** retrouvez-vous les mêmes informations que celles observées avec `curl` ?
> Oui pour l’essentiel : mêmes méthode, URL, code et contenu. Le navigateur envoie davantage d’en-têtes (User-Agent, Accept-Language, Accept-Encoding, cookies...) et peut utiliser HTTP/2 ou HTTP/3 au lieu de HTTP/1.1.


5. Chargez la page https://fr.wikipedia.org 

**Question :** combien de requêtes, et pour quels types de ressources ? Que concluez-vous sur le lien entre « une page » et « une requête » ?
>Le chargement déclenche plusieurs dizaines de requêtes (52 dan mon ordinateur avec Firefox, le nombre exact varie) : le document HTML, des feuilles de style CSS, des scripts JavaScript, des images (PNG, SVG, WebP), des polices de caractères, et parfois des appels de données (XHR/fetch).

>Conclusion : une page n’est pas une requête. Une page = une requête pour le HTML, puis une requête par ressource que ce HTML référence.
